# Телефонный справочник

Курсовая работа, тема 16. Ходунов Артемий Евгеньевич, ИБ-2514.

Программа хранит абонентов в бинарном файле, поддерживает несколько номеров с типами, поиск по ФИО и цифрам номера, сортировку, прокрутку, масштаб 80–160 %, добавление, изменение и удаление. Изменения сохраняются сразу после подтверждения.

## Быстрый запуск на Mac

1. Распаковать весь комплект. Каталог `lib` рядом с JAR обязателен.
2. Открыть `run.command`. Он использует установленный Homebrew OpenJDK, если тот найден, либо `java` из PATH.
3. Для демонстрации открыть `demo.command`. Используется отдельная учебная база.

Из терминала, находясь в каталоге PhoneBook:

```sh
java -jar dist/mac-aarch64/phonebook.jar
java -jar dist/mac-aarch64/phonebook.jar --db=examples/demo.pbk
```

Нужна Java 17 или новее. На ноутбуке проверен OpenJDK 25.0.2. Комплект `mac-aarch64` предназначен для Apple Silicon. Если macOS не запускает `.command` двойным щелчком, выполнить `sh run.command` из терминала. На JDK 25 JavaFX 21 может выводить предупреждения о нативном доступе и внутренних API; в проверенной среде они не препятствуют запуску.

## Windows x64

Установить JDK 17+ и добавить `java` в PATH. Открыть `run.bat` или выполнить из PhoneBook:

```bat
java -jar dist\win\phonebook.jar
java -jar dist\win\phonebook.jar --db=examples\demo.pbk
```

Windows-комплект собран, но запуск GUI на Windows не проверялся. Перед защитой на другом компьютере нужно выполнить пробный запуск. Windows ARM64 и Intel Mac требуют сборки с соответствующей платформой JavaFX; готовые комплекты для них не включены.

## Работа с программой

- «Добавить» открывает новую запись. Ввести ФИО, номер и тип; кнопка «+ Телефон» добавляет строки.
- «Изменить» или двойной щелчок по абоненту открывает его телефоны.
- «Удалить» требует подтверждения. Отмена не меняет базу.
- Поиск работает сразу при наборе; регистр ФИО и оформление номера не мешают поиску.
- «Я → А» меняет направление сортировки ФИО. Заголовки таблицы тоже сортируют строки.
- Ползунок увеличивает или уменьшает текст. При необходимости расширить столбец или прокрутить таблицу.

ФИО: 1-150 символов. Телефоны: от 1 до 20 у абонента, от 5 до 15 цифр в номере. Допускаются `+` в начале, пробелы, скобки и дефисы. Повтор одного номера внутри абонента запрещён. Совпадение ФИО и номера у разных абонентов разрешено.

## Где находятся данные

Рабочая база: `data/contacts.pbk` относительно текущего каталога. Скрипты запуска сначала переходят в каталог проекта. Другую базу можно выбрать параметром `--db=путь`.

Предыдущая версия: `contacts.pbk.bak`. Блокировка: `contacts.pbk.lock`. Сам файл `.lock` может оставаться после закрытия - занятость определяется системной блокировкой, а не наличием файла. Не удалять блокировку, пока программа работает.

Журнал: `logs/phonebook.log`, до трёх архивов по 2 МБ. ФИО и номера в журнал не записываются.

Восстановление:

1. Закрыть все экземпляры программы.
2. Скопировать повреждённую базу в отдельное место для сохранности.
3. Скопировать исправный `.bak` на место `.pbk`.
4. Запустить программу и проверить восстановленные записи.

Резервная копия содержит только предыдущую версию. CRC32 обнаруживает случайное повреждение, но не шифрует данные и не защищает от намеренной подмены. Для реальных контактов нужны обычные ограничения доступа к каталогу и резервное копирование.

## Сборка и тесты

В корне проекта:

```sh
./gradlew test bundle javadoc
./gradlew guiCheck
```

В Windows: `gradlew.bat test bundle javadoc`. Для первой сборки нужен интернет; готовые дистрибутивы содержат библиотеки для запуска без сети. Gradle Wrapper скачивает Gradle 9.2.1. Если PATH указывает на старый JDK, выбрать JDK 17+ через JAVA_HOME. В IntelliJ IDEA открыть папку PhoneBook как Gradle-проект и указать Gradle JVM 17+.

Сборка другой платформы:

```sh
./gradlew bundle -PtargetPlatform=win
./gradlew bundle -PtargetPlatform=mac-aarch64
./gradlew bundle -PtargetPlatform=mac
./gradlew bundle -PtargetPlatform=linux
```

Результат: `build/bundle-<платформа>/phonebook.jar` и `lib`. Переносить весь каталог. Файлы в `dist` — готовая поставка; задача bundle создаёт новый результат в build и не заменяет dist автоматически.

`guiCheck` открывает тестовое окно и использует только базу в `build/gui-check`. Проверка создаёт снимки и перезаписывает учебный пример `examples/demo.pbk`; не использовать этот файл для личных контактов. Рабочий `data/contacts.pbk` проверочный сценарий не трогает.
